# v0.9.0

新增项目 HTTP 域名转发，并按工作项、资源和连接分别展示运行状态。

## HTTP 服务

- 项目可声明多个 `*.localhost` HTTP 入口，客户端使用固定代理端口，目标服务与域名归项目管理。
- `open` 默认包含 shell、TCP 和 Web，`open --only web` 可单独启用 HTTP；Web 生命周期独立于终端。
- daemon 启动后按项目的 `http[].autostart` 自动启用服务，省略时为 true；false 服务由显式 open 启用。`web stop` 保持该项目本轮停止，下一次 daemon start/restart 重新读取策略。
- 支持 HTTP、WebSocket、SSE 和流式响应；远端隧道使用系统 OpenSSH，断线期间返回 503，并按重连策略恢复。
- 配置、域名和代理端口示例见 [Web 服务转发](../web-services.md)。

## 列表与诊断

- `ls` 默认展示已启动的项目、scratch 和临时转发组，FORWARD、WEB 列显示完整映射，目录省略。
- `project ls` 查看全部项目定义；`session ls` 查看 tmux 会话及附着客户端数；`forward ls`、`web ls` 每行展示一条映射或路由。
- `--include-inactive` 包含未启动配置；`--all` 继续表示查询全部服务器。健康状态统一显示 running，重连、失败及未知状态独立保留。
- `connection ls` 与 `ps` 展示相同的连接、PID、观测机器及资源归属表。共享 master 只列一次，本机 TCP/Web 按承载 daemon 进程合并。
- 资源列表的 `--wide` 展开连接 ID 与 PID，连接列表的 `--verbose` 保留 daemon、socket 和通道诊断。
- JSON 的 items 表示当前资源视图，connections 表示归组后的连接；原始发现数组和 hosts 快照保留。

## 升级与迁移

```sh
tdev upgrade -y
tdev upgrade --remote dev -y
```

已有项目、客户端声明和 override 可直接读取，配置 schema 与机器协议沿用 1，tmux runtime 沿用 2。HTTP 为可选新增字段；未声明 HTTP 的项目保持既有行为。首次保存旧格式时仍按现有流程迁移并保留备份，无需批量改写配置。

安装后的目标程序执行 post-install：保留既有 tmux session、pane 与 generation，刷新运行中的 daemon，并按用户授权更新内置 skill。已停止的 daemon 保持停止。配置格式转换仍由首次保存触发。

旧 daemon 的 TCP 恢复登记缺少新增资源引用时，监听及转发继续恢复；具名临时组仍可查询和停止。旧项目后台转发的项目归属暂显示未知，可用 `open server/project --only forward` 显式登记并复用现有监听，补齐新的列表关联。旧客户端重新附着后使用当前程序补齐终端引用。

旧服务端未提供会话客户端数时显示 `—`。新增 HTTP 配置应由当前版本读取和修改；编辑 HTTP 项目前先更新相关客户端和项目机器。二进制回滚保留用户配置，旧程序读取新增字段前需恢复兼容的配置备份，并保护后续修改。

`ls --type project|scratch|forward`、`web status` 和原始 JSON 快照保留兼容入口。默认 ls 过滤未启动项、session ls 的独立视图以及 ps 的默认表格属于此次输出语义调整；自动化应优先使用 --json 的当前视图数据。
