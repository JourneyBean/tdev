# v0.8.0

支持手写项目与客户端配置、按需安装 AI skill，并为源码构建自动生成 Git 开发版本号。

## 项目与客户端配置

- 项目以具名 YAML 声明目录、窗口、分屏和端口，UUID、revision 与内部快照单独保存。支持单文件、多项目文件及 include 拆分，CLI 写回保留其他项目和注释。
- 同一主配置可同时声明本机项目和 client 设置。服务器连接、SSH/重连偏好、端口覆盖、附加转发及挂载路径统一管理，client.include 支持独立片段。
- override 使用 server/project 与端口名称定位，内部绑定项目 UUID；同名项目身份变化时拒绝旧偏好。共享项目定义保持原始端口，客户端按自身需求合并。
- 项目定义继续保存在项目所在机器，客户端保存连接与覆盖设置。格式和示例见[项目与客户端配置](../configuration.md)。

## AI skill

- 二进制内置 tdev skill，提供项目、会话、转发、挂载及诊断操作指引；通过签名安装包分发。
- 安装、升级及 post-install 检测 Codex、Claude Code 和 Pi，逐项询问是否安装或更新，默认拒绝。无终端默认跳过，--skills none 显式跳过，--skills detected 显式授权检测到的目标。
- 保留用户修改并报告冲突；可用 tdev skill list/show/install 单独管理。详细目录及确认规则见[安装文档](../installation.md#ai-skill)。

## 开发构建

make build 与 make cross 自动生成 `0.8.0-git.<12 位提交哈希>[.dirty]`。匹配基础版本 tag 的干净提交使用正式版本；一次跨平台构建共用版本号。make release 沿用固定正式版本和现有签名信任链。

## tmux 兼容

停止最后一个会话后，兼容旧版 tmux 在退出期间成功返回空会话列表，正确报告会话已结束。

## 升级与配置迁移

```sh
tdev upgrade -y
tdev upgrade --remote dev -y
```

现有配置可直接读取，首次保存对应配置时自动转换并保留备份。project set/edit 将旧项目转换为简洁 YAML，保留 UUID、窗口和端口，revision 递增；setup/override 等客户端保存将 client.yaml 与 overrides.yaml 迁入主配置，保留旧文件及 .legacy.bak。

post-install 更新 tmux 运行时和 daemon，并按授权处理 skill；配置格式转换由首次保存触发。已有会话和进程继续运行，daemon 刷新期间 SSH 与转发可能短暂重连。

机器协议与项目模型 schema 保持为 1，tmux runtime 沿用 schema 2。回滚到旧程序前，恢复与该程序兼容的配置备份，并保护迁移后的后续修改；二进制回滚不逆向转换新配置。旧版升级首次遇到新增 hook 时，可用安装后的新程序补跑 post-install 或 skill install。
