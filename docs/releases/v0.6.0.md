# v0.6.0

增加安装后处理、运行中 tmux 配置迁移和服务器临时转发，修复 SSH 扩展通道类型解析。

## 临时转发与命令迁移

- `tdev forward [server] -L/-R ...` 创建服务器临时转发，至少提供一条规则。默认等监听就绪后返回，由当前客户端 daemon 后台维持；`--foreground` 前台运行，Ctrl-C 释放本次转发。
- 每次调用生成 `forward-…` 名称，多条规则作为一组管理。通过 `tdev ls --type forward` 查看，使用 `tdev stop <服务器>/<名称>` 停止。后台组支持 daemon restart 恢复，daemon stop 清除恢复登记；启动批次失败清理整组。
- `forward` 的位置参数由项目改为服务器。原 `tdev forward <项目>` 改用 `tdev open <服务器>/<项目> --only forward`；原 `forward add/remove` 改用 `tdev edit <服务器>/<项目>` 或 `edit --stdin`。删除项目映射时清理当前客户端对应的 override。
- 临时转发支持本机 TCP 和远端 SSH L/R；已有 daemon 缺少临时转发能力时提示执行 `tdev daemon restart`。

## 安装后处理与 tmux 迁移

- install、upgrade、回滚及签名安装脚本在二进制提交后调用目标版本的 post-install hooks，依次迁移当前配置的托管 tmux 会话、按需刷新运行中的 daemon。相同内容重装也会补跑；已停止的 daemon 保持停止。
- 增加 `tdev post-install`、`tdev post-install --remote <服务器>` 和机器入口 `api binary post-install`。各项独立报告结果，前一项失败后继续后续处理；失败返回 PARTIAL_SUCCESS，保留已安装二进制并支持重试。
- tmux 运行配置独立记录 schema，迁移保留 pane、进程、session generation、用户 hooks 和未读提醒。高于当前支持的 schema 返回兼容错误。缺少归属的旧 scratch 通过显式附着或 `--adopt-legacy-scratch` 认领。

## SSH 通道解析

兼容 `session:command`、`session:shell` 和 `session:subsystem:<name>`，统一保存基础类型 `session`；丢弃扩展描述及子系统参数，保留通道状态与缓冲字节。

## 首次升级步骤

从 v0.5.0 或更早的客户端升级后，用新二进制补跑一次：

```sh
tdev post-install
# 已升级的远端
tdev post-install --remote dev
```

其他配置根附加对应的 `--config-dir`。首次开启 tmux 焦点上报时，已附着的客户端按处理报告重新附着。回滚到缺少 post-install 入口的历史版本会报告部分成功，已恢复的二进制保留。

机器协议与项目配置 schema 保持为 1，新增 post-install-v1 能力，沿用现有安装签名公钥。真实 SSH/PTY、tmux、签名安装与转发覆盖及平台限制见[验收记录](../acceptance.md)。
